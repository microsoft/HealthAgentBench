# Tasks

This directory contains generated Harbor task environments for benchmark integrations.

Current benchmark tasks in this repo:

| Benchmark | Task Directory | Description | Notes |
|-----------|----------------|-------------|-------|
| **MedAgentBench** | `medagentbench/` | Interactive EHR benchmark focused on multi-step retrieval, reasoning, and structured action tasks over clinical data. | Harbor-generated benchmark task built from raw benchmark assets under `scripts/medagentbench/`. |
| **EHRSQL_Lite** | `ehrsql/` | Text-to-SQL benchmark over EHR databases (MIMIC-III, eICU). We use a lite version that covers 250 samples from MIMIC-III and 250 samples from eicu. Agent generates SQL queries or identifies unanswerable questions. |THE harbor task directories are generated using `scripts/ehrsql/generate_harbor_tasks.py`.|
| **EHR → MEDS ETL** | `ehr_to_meds_etl/` | ETL benchmark for converting the open MIMIC-IV demo dataset into MEDS by following the pinned upstream `MIMIC_IV_MEDS` repo. | Adapted Harbor task with staged demo input, agent-run `uv` setup, and directory-output verification against a gold summary. |
| **Chest X-ray Report Correction** | `xray_report_correction/` | Patient-aware multimodal radiology-report generation on MIMIC-CXR. Ten manually-curated cases (`case_01..case_10`); each task is one patient — the agent sees prior studies (images + reports + timestamps) and reviews and corrects a counterfactual draft FINDINGS for one target study. | Task tree is generated by `scripts/xray_report_correction/generate_harbor_tasks.py` from the credentialed PhysioNet release via a two-service docker-compose bootstrap. Scored by **CheXprompt** (5-vote majority, pass iff ≥3/5 zero clinically-significant errors); aggregator emits pass rate + diagnostic mean_sig_errors via a `uv-script` aggregator. See [design/related_work/xray_report_correction.md](../design/related_work/xray_report_correction.md). |
| **Tumor Area Selection Pathology** | `tumor_area_selection_pathology/` | Pathology task family with two task types: tumor slide selection and tumor area selection. One Harbor task per slide. | Task tree is generated by `scripts/tumor_area_selection_pathology/generate_harbor_tasks.py`. Public manifests come from curated public whole-slide sources; aggregate metrics report slide-selection precision / recall / F1 and area-selection tile precision / recall / F1 plus tumor coverage. |
| **MIMIC-IV-DQ** | `ehr_data_quality/` | Synthetic data-quality detection over a corrupted MIMIC-IV-demo subset. Four tasks (one per error family + a combined task) inject impossible values, conflicting/duplicate records, and demographic contradictions; the agent flags suspicious rows. Cluster-level recall + row-level precision combined into F1. | Task tree generated by `scripts/ehr_data_quality/generate_harbor_tasks.py`. Demo CSVs downloaded at Docker build time. Anti-cheat is source-name obfuscation only (no `/etc/hosts` egress block — it's read-only at image build). |
| **Clinical Trial Matching** | `clinical_trial_matching/` | Patient-to-clinical-trial retrieval (built from TREC Clinical Trials 2021). Each of 10 tasks hands the agent one synthetic admission note plus the topic's judged-pool corpus of clinical-trial XMLs and asks for a ranked NCT-ID list; scored by NDCG@10 against physician-judged graded qrels (eligible / excluded / non-relevant). | Task tree generated by `scripts/clinical_trial_matching/generate_harbor_tasks.py`. Per-topic corpus is fetched on demand from the upstream zip snapshot via HTTP range requests, cached host-side at `scripts/clinical_trial_matching/assets/raw_cache/` (gitignored), bind-mounted into each container with a per-topic `flock`. NDCG@10 via `pytrec_eval`. |
| **EHRSHOT** | `ehrshot/` | Clinical event prediction on 6,739 longitudinal EHR timelines (Wornow et al., 2023). 14 binary-classification tasks plus one 14-label multilabel (`chexpert`) covering operational outcomes (`guo_icu`, `guo_los`, `guo_readmission`), abnormal next-lab prediction (`lab_anemia`, `lab_hyperkalemia`, `lab_hypoglycemia`, `lab_hyponatremia`, `lab_thrombocytopenia`), new-onset diagnoses (`new_acutemi`, `new_celiac`, `new_hyperlipidemia`, `new_hypertension`, `new_lupus`, `new_pancan`), and chest-X-ray report-finding bitmasks. The agent sees `events.csv` (per-task leak-proof slice of the longitudinal event log) plus train/val labels and unlabeled test examples; it writes `predictions.csv`. AUROC scored against held-out test labels; reward is binary (1 iff agent AUROC ≥ count+LightGBM published baseline). | Task tree generated by `scripts/ehrshot/generate_harbor_tasks.py`. ~4 GB Redivis bundle downloaded at container bootstrap (gated access — host needs a Redivis API token at `~/.redivis/api_token`). Test labels are never committed to git: a bootstrap compose service downloads the bundle, runs `stage_data.py` to slice events and partition labels by split, and writes `test_labels.csv` to a `tests/` mount; the agent's `main` service starts only after bootstrap exits cleanly. Leak-proofing is mechanical: `/data/_cache` is not bind-mounted into `main`, and the test-slice keeps only events with `start < T_cap` while blanking any future `end` timestamps. Per-task `baseline.json` records both the count+LightGBM and CLMBR+LR baselines (hardcoded fallbacks in the generator so missing CSVs don't break task generation). |
| **CT Abnormality Detection** | `ct_abnormality/` | Chest-CT multi-abnormality classification on the CT-RATE dataset (Hamamci et al., 2024). Each of 10 tasks hands the agent one chest-CT volume (NIfTI) plus a per-volume label list (4–12 categories grounded in the paired physician report) and asks for a `<label>: yes/no` prediction per requested label. Reward is binary — the agent must get every label right to score 1.0. Cross-volume macro / micro F1 across the 17 evaluated diseases reported as diagnostics. | Task tree generated by `scripts/ct_abnormality/generate_harbor_tasks.py`; the manifest pins only volume IDs (no committed answer key). NIfTI volumes (~100–350 MB each, ~3.5 GB total) and the validation reports CSV are downloaded from Hugging Face on demand (CT-RATE is OpenRAIL-gated; `HF_TOKEN` in repo-root `.env`, loaded by the `bootstrap` service via `env_file`). Cache lives at `scripts/ct_abnormality/assets/raw_cache/` (gitignored), bind-mounted (repo-relative) into the per-task one-shot `bootstrap` compose service, which also derives the runtime `tests/gold.json` from the report via `scripts/ct_abnormality/gold_derivation.py` (gitignored). The agent's `main` service `depends_on: bootstrap: condition: service_completed_successfully` so Harbor's `docker compose up --wait` blocks the agent until the volume is staged into a shared workspace volume — same pattern as `tasks/medagentbench/`. |

For the canonical repo-level workflow for integrating a new benchmark, see `design/benchmark_addition_workflow.md`.

For benchmark-specific task generation details, see `scripts/<benchmark>/README.md`.

## Metric Definitions

For EHRSQL, **Score** refers to Execution F1 — the harmonic mean of execution precision and execution recall. Execution precision is the fraction of agent-predicted answerable queries whose results match the gold SQL results exactly. Execution recall is the fraction of gold answerable queries that the agent answered correctly. Both metrics use set-based comparison of query results against the SQLite database, which is more robust than string-based SQL matching.

## Tumor Area Selection Pathology Metric Definitions

For `tumor slide selection`, **precision**, **recall**, and **F1** are computed at the slide level on the dedicated 25-slide rerun.

For `tumor area selection`, **precision**, **recall**, and **F1** are computed over the predicted tumor-tile set on the fixed benchmark grid.

For `tumor area selection`, **tumor coverage** is the fraction of gold tumor pixels covered by the union of predicted tumor tiles.
