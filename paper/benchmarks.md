# Benchmarks

This document summarizes the benchmark tasks included in MedCLI and explains why each one belongs in a unified benchmark suite for healthcare agents. Each section is intended to answer the paper-level questions a reviewer is likely to ask: what capability the task measures, why it is medically meaningful, and what the standardized MedCLI packaging contributes beyond the original underlying resource or repository.

## mimic_iv_meds

`mimic_iv_meds` adds a medically grounded healthcare data workflow task to the suite by evaluating whether an agent can customize and execute a real EHR extraction pipeline rather than merely answer questions about structured records. Concretely, the agent must inspect an unfamiliar MEDS ETL repository, understand its default extraction configuration, create a new non-default configuration without changing the repo's default wiring, run the pipeline with that custom configuration for the current run, and produce a valid MEDS cohort output. The task is medically meaningful because success depends on making clinically coherent extraction changes, including converting admission-time demographics from flat fields into explicit timestamped events and assigning appropriate event-code families for outpatient measurements, hospital laboratory events, and ICU charted observations. This makes the task a useful complement to diagnosis, dialogue, and prediction benchmarks: it measures repository understanding, configuration-level customization, command-line execution, environment interaction, and structured EHR transformation under domain constraints that arise in real healthcare data engineering. At the paper level, the contribution is not the upstream ETL codebase itself, but the fact that MedCLI turns this kind of fragmented, implementation-heavy healthcare workflow into a standardized, executable, verifiable benchmark task that can be run consistently across agents within a common evaluation substrate.

## mimic_report_gen

`mimic_report_gen` adds the first multimodal, generative task to the suite by evaluating whether an agent can draft a clinically faithful radiology report while reasoning over a patient's longitudinal imaging history. Concretely, each Harbor trial corresponds to one MIMIC-CXR patient and one target chest-X-ray study from the official MIMIC-CXR-JPG `test` split; the agent is given the patient's prior studies (JPG images plus their free-text reports and timestamps) and the non-generative sections of the target report (EXAMINATION, INDICATION, HISTORY, TECHNIQUE, COMPARISON), and it must produce the FINDINGS and IMPRESSION sections from the target study's images. The task is medically meaningful because clinically acceptable findings and impression require combining visual interpretation of the current X-ray, comparison against the most recent relevant priors, and consistency with chronic findings documented in the report history (e.g. postsurgical clips, old fractures, persistent effusions). This is the first benchmark in MedCLI that is both multimodal and generative: success depends on repeated tool calls to actually view the images, navigation of a longitudinal on-disk patient layout, integration of visual observation with textual prior context, and the structured-output discipline required to conform to a radiology-report format that downstream pooled metrics can score. Evaluation reports per-trial BLEU-4 and ROUGE-L text-overlap scores alongside pooled CheXbert F1 computed from per-sample label vectors — the benchmark is the first in the suite to use Harbor's `uv-script` metric hook for a pooled aggregate metric that cannot be computed from per-trial scalars alone. At the paper level, the contribution is not the underlying MIMIC-CXR dataset or upstream report-generation literature, but the fact that MedCLI packages the most-studied medical image-to-text task as a patient-aware, longitudinal agentic benchmark with built-in CheXbert F1 scoring, repeatable environment bootstrap from credentialed PhysioNet assets, and a clean separation between agent-visible history and hidden target report.
