# Benchmarks

This document summarizes the benchmark tasks included in MedCLI and explains why each one belongs in a unified benchmark suite for healthcare agents. Each section is intended to answer the paper-level questions a reviewer is likely to ask: what capability the task measures, why it is medically meaningful, and what the standardized MedCLI packaging contributes beyond the original underlying resource or repository.

## mimic_iv_meds

`mimic_iv_meds` adds a medically grounded healthcare data workflow task to the suite by evaluating whether an agent can customize and execute a real EHR extraction pipeline rather than merely answer questions about structured records. Concretely, the agent must inspect an unfamiliar MEDS ETL repository, understand its default extraction configuration, create a new non-default configuration without changing the repo's default wiring, run the pipeline with that custom configuration for the current run, and produce a valid MEDS cohort output. The task is medically meaningful because success depends on making clinically coherent extraction changes, including converting admission-time demographics from flat fields into explicit timestamped events and assigning appropriate event-code families for outpatient measurements, hospital laboratory events, and ICU charted observations. This makes the task a useful complement to diagnosis, dialogue, and prediction benchmarks: it measures repository understanding, configuration-level customization, command-line execution, environment interaction, and structured EHR transformation under domain constraints that arise in real healthcare data engineering. At the paper level, the contribution is not the upstream ETL codebase itself, but the fact that MedCLI turns this kind of fragmented, implementation-heavy healthcare workflow into a standardized, executable, verifiable benchmark task that can be run consistently across agents within a common evaluation substrate.

## xray_report_gen

`xray_report_gen` adds the first multimodal, generative task to the suite by evaluating whether an agent can draft a clinically faithful radiology report while reasoning over a patient's longitudinal imaging history. Each of the 10 Harbor subtasks (`case_01` through `case_10`) corresponds to one MIMIC-CXR patient and one target chest-X-ray study; the ground-truth reports for the curated 10 were manually reviewed for clinical accuracy, so the agent is judged against high-quality reference reports. The agent sees every prior chest-X-ray study MIMIC has on record for the patient (JPG images plus their full reports), the target study's images, and the non-generative sections of the target report (EXAMINATION, INDICATION, HISTORY, TECHNIQUE, COMPARISON); it must produce the FINDINGS and IMPRESSION sections from the target study's images. The task is medically meaningful because clinically acceptable findings and impression require combining visual interpretation of the current X-ray, comparison against the most recent relevant priors, and consistency with chronic findings documented in the report history (e.g. postsurgical clips, old fractures, persistent effusions). This is the first benchmark in MedCLI that is both multimodal and generative: success depends on repeated tool calls to actually view the images, navigation of a longitudinal on-disk patient layout, integration of visual observation with textual prior context, and the structured-output discipline required to conform to a radiology-report format. 

## clinical_trial_matching

`clinical_trial_matching` adds the first **clinical-trial recruitment / patient–trial matching** task to the suite by evaluating whether an agent can read a free-text patient case and rank a topic-specific corpus of clinical-trial protocols by how confident it is the patient is eligible for each trial. Each of the 10 Harbor tasks corresponds to one TREC Clinical Trials 2021 topic — a synthetic admission-note-style case description (~5–10 sentences) — paired with the ~400–600 NCT XMLs that the upstream physician judges adjudicated for that topic. The agent is given `/workspace/data/topic.txt` and a `/workspace/data/trials/<NCT>.xml` directory (raw ClinicalTrials.gov v1 XML, with `eligibility/criteria/textblock`, demographics, condition, intervention, and brief summary populated) and must write a confidence-ordered NCT list to `/workspace/submission/ranked_trials.txt`. The task is medically meaningful because trial recruitment is a documented bottleneck in clinical research — physicians spend non-trivial chart-review time reconciling each open trial's inclusion and exclusion criteria against a patient's history and active conditions, and the upstream TREC-CT track was explicitly motivated by the prospect of automating that decision. Solving it requires combining free-text inference over the patient's diagnoses, medications, age, sex, and recent labs with structured reasoning over each trial's age bounds, condition list, and free-text inclusion/exclusion clauses, then committing to a *ranking* rather than a set so that ambiguous and partial-match cases are preferred over outright exclusions. This is the first benchmark in MedCLI that uses a graded retrieval metric: per-trial reward is **NDCG@10** with linear gain over the qrels (eligible=2, excluded=1, non-relevant=0), normalized by the topic's ideal DCG so scores are comparable across topics; the reward field that Harbor reads is reduced to a binary 0/1 (1 iff NDCG@10 == 1.0) so pass/fail counting carries a meaningful "perfect top-10" interpretation, while the underlying graded NDCG@10 is preserved as a per-trial metric for variance reporting. Set-based F1 / precision / recall against the eligible class and rank-aware P@10 / R@10 are reported as diagnostics, and `aggregate_metric.py` pools per-topic NDCG@10, the integer pass count, and the pass rate alongside macro / micro F1 via Harbor's `uv-script` metric hook. At the paper level, the contribution is not the underlying TREC-CT 2021 task or the qrels themselves but the fact that MedCLI packages a 75-topic, 35 K-judgment benchmark as an executable agentic task with on-demand per-topic corpus fetching from the upstream zip snapshot via HTTP range requests (~5 min/topic cold, host-cached afterwards), a global `flock` plus bootstrap-sentinel handshake that lets concurrent containers cold-fetch without hammering the upstream server or starting agents over an empty `/workspace/data/trials/`, and a verifier that emits both the graded NDCG@10 reward and the pass-rate / set-based diagnostics needed to compare ranking quality and eligibility coverage in the same run.
## ct_abnormality

`ct_abnormality` adds the first **3-D imaging interpretation** task to the suite by evaluating whether an agent can read a chest CT volume and decide, for each of a short list of clinically meaningful findings, whether the finding is present or absent. Each of the 10 Harbor subtasks corresponds to one CT volume drawn from the validation split of CT-RATE (Hamamci et al., 2024), the largest publicly accessible chest-CT-with-reports dataset to date. The agent is given a single NIfTI volume at `/workspace/data/scan.nii.gz` (axial chest CT, 512×512 to 1024×1024 in-plane, 200–700 slices, intensities in Hounsfield Units) plus a per-volume label list at `/workspace/data/labels.txt` containing 4 to 12 categories — exactly those whose value is unambiguously grounded in the paired physician report — and must write a `<label>: yes/no` line per requested label to `/workspace/submission/predictions.txt`. The task is medically meaningful because chest CT is the single highest-volume cross-sectional radiology study in modern hospitals; each scan combines lung parenchymal patterns (nodules, ground-glass opacity, consolidation, mosaic attenuation, septal thickening, bronchiectasis, peribronchial thickening, pulmonary fibrotic sequelae), pleural and pericardial findings, mediastinal and hilar lymphadenopathy, cardiac size, vascular calcifications and atheroma, and incidental medical material (stents, catheters), and a generalist agent that can reliably extract these findings would meaningfully reduce radiology workload. This is the first benchmark in MedCLI that requires the agent to *select-and-use a vision tool* rather than read pre-rendered text or images: the canonical agent workflow is to load the volume with `nibabel`, render axial slices to PNG with `pillow`, view them with whatever multimodal capability the harness provides, and decide each label from those views. Per-volume reward is **binary** — 1.0 iff every requested label exactly matches gold, 0.0 otherwise — which makes Harbor's `Successes` column carry a meaningful "perfect chest CT read" interpretation; cross-volume metrics report `pass_rate`, integer pass count, per-disease F1 across the 17 evaluated CT-RATE categories (Pulmonary fibrotic sequela was dropped because no volume retained it under the strict-wording rule), plus pooled macro and micro F1, all aggregated through Harbor's `uv-script` metric hook. At the paper level, the contribution is not the underlying CT-RATE dataset or its silver predicted labels, but the fact that MedCLI re-derives gold per volume from the radiology report under a strict exact-wording rule (so every label has a verbatim evidence quote and pass-rate reporting is deterministic), pins a stratified 10-volume manifest spanning a normal scan through a 12-positive heavy case, runs a one-shot `bootstrap` docker-compose service that downloads ~3.5 GB of NIfTI from a Hugging Face gated repository on demand under a global `flock`, and waits for it to exit cleanly via `depends_on: condition: service_completed_successfully` before the agent's `main` container is started — the same compose-level synchronization pattern as `tasks/medagentbench/`, which keeps task-specific bootstrap logic out of the installed-agent harness wrappers. The whole package is an agentic chest-CT benchmark whose reward semantics make a perfect attempt unambiguous.

## tumor_area_selection_pathology

`tumor_area_selection_pathology` adds a pathology-native visual reasoning task family to the suite by evaluating whether an agent can navigate whole-slide images, combine imperfect inspection signals, and produce structured tumor predictions without training a custom model. Concretely, the benchmark has two linked task types under one Harbor packaging scheme. In the `tumor slide selection` task, each Harbor trial is one public whole-slide image and the agent must decide whether the slide contains tumor, producing a binary output that contributes to slide precision, recall, and F1. In the `tumor area selection` task, each Harbor trial is one public whole-slide image with hidden gold segmentation; the agent must predict the complete set of tumor tiles on a fixed 256x256 analysis grid, and the benchmark reports tile-level precision, recall, and F1 using a 20%-tumor-area threshold per tile. The task is medically meaningful because both slide triage and tumor-region localization are core steps in digital pathology workflows, and both depend on deciding where to look on gigapixel images rather than merely classifying already-cropped patches. The standardized MedCLI contribution is not the underlying public datasets themselves, but the fact that the benchmark turns them into a reproducible Harbor-first agent task family with one task per slide, hidden gold labels, repeatable public-data bootstrap, a shared pathology tool surface (navigation, tissue heuristics, neighborhood exploration, and weak tile scoring), and pooled aggregate metrics that separate slide-level and tile-level performance.

## ehrshot

`ehrshot` adds the first **longitudinal clinical event prediction** task family to the suite by evaluating whether an agent can read a patient's full EHR timeline up to a moment in time and predict a clinically meaningful next event — operational, laboratory, or diagnostic — without being told which concept codes matter. Each of the 15 Harbor tasks corresponds to one published EHRSHOT prediction problem (Wornow et al., 2023, "EHRSHOT: An EHR Benchmark for Few-Shot Evaluation of Foundation Models") drawn from the same 6,739-patient Stanford Healthcare cohort: three **operational outcomes** (`guo_icu` ICU transfer at admission, `guo_los` long length-of-stay, `guo_readmission` 30-day readmission), five **abnormal next-lab predictions** (`lab_anemia`, `lab_hyperkalemia`, `lab_hypoglycemia`, `lab_hyponatremia`, `lab_thrombocytopenia`), six **new-onset diagnoses** evaluated at well-defined risk-window anchors (`new_acutemi`, `new_celiac`, `new_hyperlipidemia`, `new_hypertension`, `new_lupus`, `new_pancan`), and one **multilabel chest-X-ray finding** task (`chexpert`) where each label encodes presence of one CheXpert finding extracted from the paired radiology report. The agent receives `/workspace/data/train_labels.csv`, `/workspace/data/val_labels.csv`, an unlabeled `/workspace/data/test_examples.csv`, and a per-task leak-proof slice of the longitudinal event log at `/workspace/data/events.csv` (one flat table with `patient_id, start, end, code, value, unit, visit_id, omop_table` rows from `condition_occurrence`, `drug_exposure`, `measurement`, `procedure_occurrence`, `visit_occurrence`, `observation`, `note`, `device_exposure`, `death`, `person`; codes prefixed with `SNOMED/`, `LOINC/`, `RxNorm/`, `CVX/`, `ICD10PCS/`, `CPT4/`, plus demographic/visit metadata like `Gender/F`, `Race/...`, `Visit/IP`); it must write a continuous probability per test row to `/workspace/submission/predictions.csv`. The task family is medically meaningful because every problem reflects a documented hospital workflow — ICU triage, anticipating abnormal labs before they're drawn, surveilling for emerging chronic disease, and structuring radiology findings into chart-codable categories — and because reading these signals from a *raw* timeline rather than from pre-engineered features measures the open-ended capability that distinguishes a generalist agent from a narrow classifier. This is the first benchmark in MedCLI that combines **longitudinal raw-event reasoning** with **gated, mechanical leak-proofing**: the EHRSHOT bundle is gated behind a Redivis access agreement (host needs an API token at `~/.redivis/api_token`), so test labels are never committed to git — a one-shot `bootstrap` docker-compose service downloads the ~4 GB bundle on demand, runs `stage_data.py` to slice the event log and partition labels by Stanford's published patient split, and writes `test_labels.csv` to a host `tests/` bind-mount that is **not** mounted into the agent's `main` container; on the `main` side, only `events.csv` slices with `start < T_cap` are kept and any future `end` timestamp is blanked, so multi-day visit rows can disclose "patient is admitted at T" but cannot leak the discharge timestamp that resolves tasks like `guo_los`. Reward is **binary per task**: 1.0 iff the agent's test AUROC meets or exceeds the published count+LightGBM baseline AUROC scored on the same last-row-per-patient test subset (Δ ≥ 0; for `chexpert` the mean AUROC across the 14 finding columns is used), and per-task `baseline.json` ships both the count+LightGBM baseline and the CLMBR+LR foundation-model baseline so per-trial reports can position agent AUROC against both (hardcoded fallbacks in the generator make the task tree build cleanly even when the per-task baselines CSV is absent). Per-trial reports include `auroc`, `auprc`, `brier`, `n_test`, and `baseline_auroc`; `aggregate_metric.py` pools per-task pass count, pass rate, mean AUROC across tasks, and mean baseline AUROC via Harbor's `uv-script` metric hook so a single sweep produces a comparable per-model summary table. At the paper level, the contribution is not the EHRSHOT bundle or the upstream foundation-model baselines themselves but the fact that MedCLI packages a 15-task, raw-timeline, gated-data clinical-prediction benchmark as a reproducible Harbor-first agentic task family — with one-click container-side data download for the user, hidden test labels enforced by docker-compose volume topology, mechanical leak-proofing on the event slice, and pass-the-baseline pass/fail semantics that make a sweep's `Successes` column reflect whether an agent legitimately beats the published count-features baseline on real longitudinal EHR.

## mimic_iv_dq

`mimic_iv_dq` adds the first **data-quality auditing** task to the suite by evaluating whether an agent can detect deliberate, clinically-grounded errors injected into a structured EHR dataset. Each of the five Harbor tasks hands the agent a corrupted MIMIC-IV-demo subset (eight hospital and ICU tables) under `/workspace/data/csv/` and asks it to flag rows it believes are problematic. Four error families — *impossible values* (range violations, decimal shifts, unit confusions, valueuom mismatches), *temporal inconsistencies* (discharge before admission, medication started after discharge), *conflicting / duplicate records* (in-table duplicates with disagreeing values, cross-table lab-versus-chart conflicts at the same patient and timestamp), and *demographic contradictions* (patient gender flipped relative to a strongly gender-marker drug, or age mutated to a value implausible for a geriatric drug) — make up four per-family tasks; a fifth `task_combined` task mixes all four. The task is medically meaningful because EHR data-quality issues are a documented source of clinical-decision-support failures, cohort-construction bias, and downstream-model error: detecting them requires combining hard physiological-range knowledge, statistical reasoning over per-itemid distributions, multi-table joins for time-order checks, and clinical priors that link drugs to patient demographics. This is the first benchmark in MedCLI that asks the agent to *audit* rather than transform or interpret EHR data, and the first whose ground-truth labels include multi-row clusters where any row in the cluster catches the cluster — so the verifier credits the agent for identifying the suspicious *event*, not a particular row identifier. Evaluation reports per-trial cluster-level recall, row-level precision, and F1 (the harmonic mean), pooled across trials with both macro and micro aggregates plus a per-family / per-subtype recall breakdown via Harbor's `uv-script` metric hook. At the paper level, the contribution is the design of a deterministic, reproducible synthetic-error benchmark over an open EHR substrate (no upstream paper or dataset exists for this exact task) with hidden labels that survive byte-level alignment with build-time corruption, anti-cheat defenses against trivial diff-against-pristine attacks (source-name obfuscation in agent-facing artifacts plus runtime PhysioNet egress blocking via `/etc/hosts`), and a packaging that turns a documented but un-benchmarked clinical-engineering responsibility — auditing EHR data quality — into an executable, verifiable, agentic task.
